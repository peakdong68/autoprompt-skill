# DeepSeek Harness 模式契约

`SKILL.md` 是权威依据。本文件定义运行时调节旋钮，且不得重新引入旧式工作流治理。

## 路线图优先不变量

新运行在选择器（chooser）结束后即开始有用优先的工作。没有单独的 intake 往返、强制 preflight 智能体、scope-map 或独立的规划官僚流程。带有完整绑定的受信任启动证明可以跳过探测；否则，第一位路线图作者必须先在一个一次性草稿路径上验证 RUN、READ 和 WRITE，然后直接进入仓库检查。失败会在构建之前硬停止。

Scope 阶段产出唯一权威、可执行的 `ROADMAP.md`：

- **有界 scope = 3 个智能体，2 轮**，目标 **一分钟以内**：路线图作者，随后并发执行独立评审者与盲测新鲜验证者；
- **多表面 scope = 恰好 5 个智能体，3 轮**，目标 **五分钟以内**：保留完整的作者路线图与证据，恰好增加两名互补侦察员，然后评审者与盲测新鲜验证者并发执行，不做冗余的普通综合调度；
- **超大 scope：** 只有出于记录在 `GATELOG.md` 中的具体理由，才允许超出 6 智能体的常规 scope 预算。

被否决时，保留已接受的证据，只修复点名的缺陷。获批的路线图拥有范围、稳定条目 id、依赖边、启动分组、文件/表面所有权、集成、验收、不愉快路径、测试、覆盖率与真实验证的决定权。可直接实现的条目直接派发；只有当路线图标记需要、debug/depth-lock 工作、存在点名的未决设计分叉，或工作者报告计划冲突时，才加入详细规划。

新运行的治理**恰好是三个文件**：

1. `PROMPTS.txt` —— 精确的只追加提示词块；
2. `ROADMAP.md` —— 唯一可执行的范围/分解/计划来源；
3. `GATELOG.md` —— 只追加的状态流转、来源、裁决、耗时、假设、升级原因与恢复前沿。

不得创建仅用于治理的 `BRIEF.md`、`PLAN.md`、`AGENTS.md`、`COVERAGE.md`、`BACKLOG.md`、`ANCHOR.md`、`bucketlist.md`、`intake.md`、`scope-map.md`、按角度拆分的 scope 文件或等价物。实质性的实现、测试、评审与验证证据仍然有效。旧格式**仅限恢复使用**：只在继续已有运行时读取它们，绝不为新运行生成它们。矛盾的混合治理一律失败关闭。

在第一位作者把精确任务存储进 `PROMPTS.txt` 之后，简报使用紧凑的任务指针：

```text
MISSION POINTER: verify the exact prompt ledger before acting.
path=<PROMPTS.txt> hash=sha256:<64 hex> bytes=<UTF-8 byte length> nonce=<RUN-NONCE>
```

只包含角色、目标、负责边界、依赖关系、验收标准、经哈希的路线图/证据指针、输出契约以及真实的模型/effort 状态。不要在每个简报里粘贴完整任务、完整路线图、对话记录、教条或先前的对抗性推理。工作者行动前验证指针；盲评者保持盲态。

## 正交的运行时旋钮

并发度、值守方式（attendance）、智能体选择与路线图工作形态相互独立。并发度改变多少个就绪智能体同时运行；智能体选择只改变模型与推理 effort；二者都不改变路线图的门禁或依赖关系。

### 并发度

| 模式 | 契约 |
|---|---|
| `tokensaver` | 默认。最多 6 个存活智能体，并受运行时上限进一步约束。 |
| `wide` | 把所有就绪且真正互不相交的通道一起派发，直至运行时/全局上限。 |
| `billionaire` | `wide` 的受认可的旧式拼写；无独立语义。 |
| `custom max_subs=N` | 宽派发，附带显式的正整数存活智能体上限。 |

运行时任务上限始终是硬性封顶；`max_subs` 只能调低它。限制是天花板，不是目标。复用有效证据，去重所有权，绝不为填满容量而 spawn 智能体。单条有界通道跳过 L2；互不相交的就绪通道一起启动，遵循 spawn-all-then-collect：先发出一个就绪组的所有 spawn，再收集任何报告 —— 并行后台派发是默认形态；只有声明的真实依赖才允许串行化。当三条或更多通道就绪且可达成宽度至少为三时，必须至少有三个工作者并发运行；更低的显式上限仍然真实有效。流式处理完成结果，而不是等待整波结束。

每次派发都是 collect-then-stop：收集到最终报告后立即显式停止该智能体；处于驻留可恢复状态的智能体仍然是存活智能体，会占用上限。DONE 要求零个存活子智能体。

受认可的指令是 `mode=tokensaver|wide|billionaire|custom`、行首裸模式词，以及 `max_subs=N`。从任务中剥离运行时指令。拒绝无效的自定义上限，而不是悄悄编造一个。

### 选择器与值守

只有在进入仓库/工具工作之前，才解析未定义的操作者旋钮。在有人值守会话中，对所有缺失值一次性询问：

- 并发度：Tokensaver、Wide 或 Custom；
- 智能体选择：仅 Inherit；
- effort 能力：精确报告 `inherited-only`。

不要让用户复述、收窄或批准使命。在监督者启动的无人值守运行中绝不询问：缺失的并发度默认为 `tokensaver`，缺失的智能体选择默认为 `off`，并把这两个假设记入 `GATELOG.md`。仅有权限绕过标志并不能使一次运行成为无人值守。

显式操作者控制确定性地覆盖无人值守默认值；任何旋钮冲突都按有利于操作者的方向解决并记入 `GATELOG.md`，绝不能把它推迟成静默默认值。

仲裁者裁决技术性分叉。运行中向用户提问仅限于用户所有的不可逆/破坏性操作、真实金钱或配额、不可用的凭据或产品方向问题。能力失败、阻塞、覆盖率与真实验证不能被仲裁豁免。

### DeepSeek Harness 智能体选择与 effort

DeepSeek Harness 的 casting 是 `inherited-only`：Autoprompt 代理预设中的固定角色 `dsh-tool-subagent` 实例不带模型覆盖，继承所选父模型。

- `agents=off` 或省略：唯一可路由的模式；每个角色继承所选模型。
- `agents=auto`、`agents=<comma-list>` 与 `agents=auto:<comma-list>`：不可路由；记录 `inherited-only`，绝不声称应用了某种选择。

effort 一律记录为 `inherited-only`：省略任何 effort 字段，绝不声称应用了某个请求的或最大的 effort。

Web 会话请选择 Autoprompt 代理预设。无头（headless）运行时，通过 `--patch` 传入已安装的 `headless.patch.yml`。每个角色工具都会拒绝白名单之外的角色工具，并使用不超过四层的深度上限。

## 引导、恢复与权限

非紧急引导（steer）会排队进入下一次续跑，并作为下一条精确提示词块追加到 `PROMPTS.txt`；现有工作继续进行。明显使存活工作失效的引导属于紧急引导：先在 `GATELOG.md` 中为前沿做检查点，然后取消、追加提示词块，并从检查点重新派发。绝不在检查点之前取消。

恢复必须是显式的：只有显式的 `resume` 指令或监督者重启才能恢复一次运行。恢复上下文只读取 `GATELOG.md` 尾部 —— 最后的前沿行 —— 校验其任务指针哈希，并用紧凑的指针简报派发开放前沿。由工作者（而非恢复上下文）阅读 `ROADMAP.md` 章节与实质性证据。空、临时、畸形或哈希不匹配的工件一律视为不存在。重新验证最后接受的前沿并幂等地继续。旧式台账可以提供恢复前沿，但绝不能用新的旧式治理文件扩展它。

调用 Autoprompt 或处于无人值守模式都不暗示任何外部或 git 操作。未经用户明确授权，**不得** commit、push、publish、deploy、花钱、删除用户数据、force-push、hard reset 或清理工作树。监督者只提供重启/恢复能力；它不授予任何发布或 git 权限。
